01 / A TURING MACHINE

什么构成一台图灵机？

纸带由无限多个格子组成，每格存一个有限字母表中的符号。磁头每次读取当前格；有限控制器保存当前状态。转移函数决定下一状态、写入内容和磁头移动方向。

δ(q, a) = (q′, b, d)

本项目的目标机器使用符号 0、1、B。B 是空白；L 和 R 分别移动一格；H 是「写入后停机」的简写，不移动磁头。它可以直接改写成传统的停机状态。

一元加法为什么成立？

输入 110111 表示 2 + 3。把分隔符 0 写成 1，会多出一个 1；再到最右侧擦去一个 1，剩下五个 1。状态 q1 负责寻找分隔符，q2 找到末尾，q3 擦除并停机。

02 / A UNIVERSAL MACHINE

把机器本身，写在纸带上。

U 的转移表是固定的。加法或取反的规则不在它的控制代码里，而在第一条纸带上。U 扫描程序、比较状态和符号，找到规则后，修改第二条和第三条纸带。

U(〈M〉, x) ≃ M(x)
程序带 P
用固定格式编码 M 的全部规则；U 只读这条带。
模拟带 T
就是 M 的纸带，模拟带的磁头就是 M 的磁头。
状态带 Q
用一元编码保存 M 当前状态，如 q3 写成 ^111。

更换目标程序只会更换初始纸带。U 的状态集、字母表和 3,656 条转移规则始终不变。

03 / FOLLOW THE ENCODING

一条规则，在纸带上是什么样？

1 : 0 : 11 : 1 : R |
当前 q1读取 0转到 q2写入 1向右结束

完整程序以 ^ 开头，以 $ 结束。状态编号采用非空一元串，字段以 : 分隔，规则以 | 分隔。B 在纸带上就是一个真正的空白格；即使出现在程序字段里，也由相邻分隔符确定它的位置。

UTM 的一步与 M 的一步

U 的一个微步只执行一条 δU：同时读取三个磁头下的符号，同时写入、移动三个磁头，并改变 U 的有限控制状态。模拟 M 的一步通常需要许多微步。状态比较、旧状态擦除、新状态复制和磁头复位，每一项都由这些规则完成。

为什么它是通用的？

它可解释任意有限的确定性单带 0/1/B 图灵机，状态数量不固定。任意有限字母表图灵机均可用二进制块编码转成这一类机器；S（不动）可用两步 R、L 展开。浏览器对输入长度、状态编号和运行步数设有资源上限，数学模型中的纸带和运行时间不受这些界面上限限制。

如何核验，而不是相信动画？

网页的 U 运行器只按固定 JSON 转移表执行。Python 定义生成完整表；独立的目标机器运行器负责在每个宏步边界核对纸带、磁头、状态和停机结果。测试还逐行检查 JavaScript 使用的表与 Python 表相同。
